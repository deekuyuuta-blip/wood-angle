# FX5UC テストプログラム（木材角度判別）

FX5UC（ファームウェア 1.110以降）で、アプリとのやり取りを確認するためのラダーです。
機械につながっていないPLCで試してください。

## 1. シンプルCPU通信の設定
ナビゲーション → パラメータ → FX5UCCPU → ユニットパラメータ → Ethernetポート

- 基本設定：自ノードのIPアドレスを、スマホと同じネットワークにする（例 192.168.3.39）
- アプリケーション設定 → シンプルCPU通信設定 →「使用する」→ 詳細設定

| 交信パターン | 交信先 | 自局（PLC） | 交信先（スマホ） | 点数 |
|---|---|---|---|---|
| 書込み | SLMP対応機器（QnA互換3Eフレーム）、スマホのIP、ポート5000 | D2000 | D0 | 1 |
| 読出し | 同上 | D2100 | D100 | 9 |

交信周期は200ms程度から。書込み後にPLCをリセット（または電源の入れ直し）。

## 2. 使うデバイス
| デバイス | 内容 |
|---|---|
| X0 / M100 | 手動で1回判別（X0のボタン、またはデバイスモニタで M100 をON） |
| M101 | ONの間、3秒ごとに自動で判別（連続テスト） |
| M102 | ONで回数カウンタをクリア |
| D2000 | 撮影要求番号（→ スマホ D0） |
| D2100〜D2108 | スマホからの結果（D100〜D108）：完了番号・結果・基準面の向き・形・平ら面ビット・傾き・信頼度・ハートビート・処理時間 |
| M200 | 判別待ち |
| M300 | OK（基準面が下） |
| M301 | 向き違い（上・左・右） |
| M302 | NG・カメラ異常・タイムアウト |
| M211 | スマホ停止（ハートビートが3秒変化しない） |
| D2300〜D2307 | 回数：下(OK) / 上 / 左 / 右 / NG / カメラ異常 / タイムアウト / 要求回数 |
| D2311〜D2313 | 形の回数：背板 / 平行板 / 食パン形（判別できたとき） |
| D2320〜D2328 | 最後に完了した結果のコピー |

実際のランプを点けたいときは、M300〜M302 の SET/RST 先を Y に変えてください。

## 3. ラダー
`─[ ]─` a接点、`─[/]─` b接点、`─[↑]─` 立上り、`─[= A B]─` 比較接点。上から順に入力してください（順番に意味があります）。

```
(1) 要求のきっかけ（1スキャンだけ M150 がON）
──[↑ X0]──┬──[/ M200]────────────────────────(M150)
──[↑ M100]─┤
──[↑ T10]──┘

(2) 連続テストの間隔 3秒
──[ M101]──[/ M200]──[/ M150]───────────────(T10 K30)

(3) 要求番号を進める・判別待ちにする
──[ M150]──────────────────────┬─[INC  D2000]
                                ├─[INCP D2307]
                                └─[SET  M200]

(4) 32767 の次は 1 に戻す（0 は使わない）
──[ M150]──[< D2000 K1]─────────[MOV K1 D2000]

(5) タイムアウト 2秒
──[ M200]────────────────────────────────────(T200 K20)

(6) 完了（スマホの完了番号 = 要求番号）
──[ M200]──[= D2100 D2000]───────────────────(M201)

(7) 完了時：ランプを消して結果を保存
──[ M201]──────────────────────┬─[ZRST M300 M302]
                                └─[BMOV D2100 D2320 K9]

(8) 結果1（判別できた）のとき、向きごとに数える
──[ M201]──[= D2101 K1]──┬──[= D2102 K1]──┬─[INCP D2300]   下（OK）
                          │                 └─[SET  M300]
                          ├──[= D2102 K2]────[INCP D2301]   上
                          ├──[= D2102 K3]────[INCP D2302]   左
                          └──[= D2102 K4]────[INCP D2303]   右

(9) 向き違い・形の回数
──[ M201]──[= D2101 K1]──[<> D2102 K1]───────[SET M301]
──[ M201]──[= D2101 K1]──┬──[= D2103 K1]────[INCP D2311]   背板
                          ├──[= D2103 K2]────[INCP D2312]   平行板
                          └──[= D2103 K3]────[INCP D2313]   食パン形

(10) NG・カメラ異常
──[ M201]──[= D2101 K2]──────────┬─[INCP D2304]
                                  └─[SET  M302]
──[ M201]──[= D2101 K3]──────────┬─[INCP D2305]
                                  └─[SET  M302]

(11) 判別待ちを終える
──[ M201]────────────────────────────────────[RST M200]

(12) タイムアウト
──[ T200]──────────────────────┬─[INCP D2306]
                                ├─[ZRST M300 M301]
                                ├─[SET  M302]
                                └─[RST  M200]

(13) ハートビート監視（D2107 が3秒変わらなければスマホ停止）
──[= D2107 D2310]────────────────────────────(T210 K30)
──[<> D2107 D2310]───────────────────────────[MOV D2107 D2310]
──[ T210]────────────────────────────────────(M211)

(14) 回数クリア
──[↑ M102]─────────────────────┬─[FMOV K0 D2300 K8]
                                ├─[FMOV K0 D2311 K3]
                                └─[RST  M102]
```

T は100ms単位なので、K30 = 3秒、K20 = 2秒です。

## 4. 確かめ方
1. スマホでアプリを開き「待受開始」。画面に出るスマホのIPを、シンプルCPU通信の交信先にする
2. 数秒たって M211 がOFFなら通信できています（D2107 が1秒ごとに増える）
3. M100 をON（または X0）→ D2000 が1増え、0.5秒ほどで D2100 が同じ番号になる
4. 木材の向きを変えながら繰り返し、D2102（基準面 1=下・2=上・3=左・4=右）、D2103（形 1=背板・2=平行板・3=食パン形）、M300〜M302 を確認
5. M101 をONにすると3秒ごとに自動で判別。D2300〜D2307 で回数を見て、取りこぼしや誤判別がないか確かめる

**つながらないとき**
- M211 がONのまま：スマホのIP・ポート、PLCとスマホが同じネットワークか、アプリの「待受開始」を確認
- アプリのログに「接続拒否」：アプリ設定の「PLCのIPアドレス」とPLCのIPが違う（空欄にすれば制限なし）
- 毎回タイムアウト（D2306 が増える）：アプリが前面に出ているか、画面が消えていないかを確認
