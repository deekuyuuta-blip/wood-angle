# 木材角度判別（Android）— シンプルCPU通信版

スマホのカメラで木材の**回転角度（傾き）**を測り、PLCの撮影要求に応えて結果を返すアプリです。
通信はSLMPモニタと同じく、スマホが「SLMP対応機器（QnA互換3Eフレーム）」として待ち受け、R04CPU（iQ-R）の**シンプルCPU通信**で要求の書込み・結果の読出しをしてもらいます。PLC側はパラメータ設定と、要求・結果を扱う少しのラダーだけです。

```
R04CPU ──(シンプルCPU通信／SLMP 3E・TCP)──▶ Wi-Fi ──▶ スマホ（このアプリが待受＋カメラ）
  書込み：PLCの D2000（撮影要求番号）       → スマホの D0
  読出し：スマホの D100〜D107（判別結果）   → PLCの D2100〜D2107
```

## 角度の決め方
- 画面の**右方向を 0°**、**反時計回り（左回り）が＋**、範囲は **-90.0°〜+90.0°**（0.1°単位）
- 木材の「軸の傾き」だけを測ります。元口・末口（どちら向きか）は区別しません
- ±90°付近（ほぼ縦向き）では、わずかな差で +89.9° と -89.9° が入れ替わります。縦向きの木材を扱うときは、スマホを90°回して付けるか「基準角度」で 0° 付近に来るようにしてください
- 「基準にする」で、今の向きを 0° にできます（基準の木材をまっすぐ置いて押す）

## 判別のしかた（設定で選ぶ）
| モード | 向いている場面 | しくみ |
|---|---|---|
| 輪郭（初期値） | 木材全体（または大部分）が画面に入る | 背景との明るさの差で木材を切り出し、形の長手方向（主軸）を求める |
| エッジ | 木材が画面からはみ出す・画面いっぱいに映る | 画面内の縁や木目の向きの平均を求める |

画面では、黄色の点線＝判別範囲、緑＝木材と判定した画素（エッジモードは強いエッジ）、赤い線＝測った軸、水色の点線＝基準角度です。

**うまく測るコツ**
- スマホはブラケット等でしっかり固定する（動くと基準がずれる）
- 背景は木材と明るさが違う色にする（暗い木材なら明るい背景、など）。日光が直接当たる場所は避ける
- 暗いときは「ライト」でスマホのライトを点ける
- 「範囲設定」で、木材が来る場所だけを指でなぞって囲む（ローラーや柱が入らないように）
- 「信頼度」は輪郭モードなら細長さ（正方形に近いほど低い）、エッジモードなら向きのそろい具合です

## PLCとの受け渡し
### PLC → スマホ（PLCがシンプルCPU通信で書込む）
| スマホのデバイス | 内容 |
|---|---|
| D0 | 撮影要求番号。判別させたいとき **1〜32767 の新しい番号**を書く（0は要求なし） |

番号が変わるたびに1回判別します。同じ番号のままなら判別しません。0 にすると完了番号・結果も 0 に戻ります。

### スマホ → PLC（PLCがシンプルCPU通信で読出す）
| スマホのデバイス | 内容 |
|---|---|
| D100 | 完了番号。判別が終わると要求番号と同じ値になる |
| D101 | 結果　1=OK　2=NG（木材が見つからない・信頼度不足）　3=カメラ異常 |
| D102 | 角度（0.1°単位の符号付き。例 123 = +12.3°、-450 = -45.0°） |
| D103 | 木材の中心X（画面幅を 0〜1000） |
| D104 | 木材の中心Y（画面高さを 0〜1000） |
| D105 | 信頼度（0〜100） |
| D106 | ハートビート（1秒ごとに+1） |
| D107 | スマホの処理時間 [ms]（要求を受けてから結果を書くまで） |

- 8ワードは1回でまとめて書くので、PLCが途中の値を読むことはありません。**D100（完了番号）＝要求番号になったら、D101〜D105 を使ってください**
- 要求を受けてから「待ち時間」（初期150ms）より後に届いた画像を「平均枚数」（初期3枚）だけ使い、その平均を返します。要求前の古い画像は使いません
- デバイス番号（D0・D100）は設定で変えられます

### 応答時間のめやす
スマホの処理は 待ち時間150ms＋画像3枚（約100ms）で約250ms。これにシンプルCPU通信の交信周期（書込み・読出し）が加わります。交信周期200msなら、要求から結果まで約0.4〜0.6秒です。急ぐときは待ち時間・平均枚数・交信周期を減らしてください。

## スマホ側
1. PLCと同じネットワークのWi-Fiにつなぐ。**IPアドレスは固定**にする（Wi-Fi詳細設定で静的IP、またはルータでDHCP予約）
2. アプリを開き、カメラの使用を許可する（画面は横向き固定）
3. 「⚙ 設定」で、PLCのIP・待受ポート（例 5000）を設定して「保存」
4. 「待受開始」（設定で起動時に自動開始もできる）。画面に出る「このスマホのIP」をPLC側の交信先IPに設定する
5. 「範囲設定」で判別範囲を決め、木材を置いて「テスト判別」で確認。必要なら「基準にする」
6. アプリは前面に開いたままにする（画面は自動で消えません）。設定画面を開いている間や画面が消えている間はカメラが止まり、要求には「3＝カメラ異常」を返します

## PLC側（GX Works3・R04CPU）
### シンプルCPU通信の設定
1. ナビゲーション → パラメータ → R04CPU → ユニットパラメータ → 基本設定で、自ノードのIPアドレスを設定（スマホと同じネットワーク）
2. 応用設定 → シンプルCPU通信設定 →「使用する」→ 詳細設定
3. 次の2行を設定する（交信先の機種：SLMP対応機器（QnA互換3Eフレーム）、IP：スマホのIP、ポート：アプリの待受ポート）

| 交信パターン | 自局（PLC） | 交信先（スマホ） | 点数 |
|---|---|---|---|
| 書込み | D2000 | D0 | 1 |
| 読出し | D2100〜D2107 | D100〜D107 | 8 |

4. 交信周期は100〜200ms程度から。書込み後、PLCをリセット（または電源再投入）

設定画面の項目名はGX Works3のバージョンで多少違うことがあります。正確な手順はMELSEC iQ-R Ethernetユーザーズマニュアル（応用編）の「シンプルCPU通信機能」を確認してください。

### ラダーの例（考え方）
デバイスは例です。現場のラダーに合わせて置き換えてください。

```
【撮影要求】 木材が停止して判別してよい状態（例 M10）の立上りで
   D2000 を +1（32767 の次は 1 に戻す。0 は使わない）
   M2000（判別待ち）を SET、T2000（タイムアウト 2秒）を開始

【完了】 M2000 かつ D2100 = D2000 のとき
   M2000 を RST
   D2101 = 1 → OK：D2102（角度 0.1°）を使う
   D2101 = 2 → NG（木材なし・信頼度不足）
   D2101 = 3 → カメラ異常

【タイムアウト】 M2000 かつ T2000 がON（D2100 が要求番号にならない）
   → スマホ停止・通信異常として扱う

【監視】 D2106（ハートビート）が3秒以上変化しない
   → スマホ停止。シンプルCPU通信の交信状態（SM/SD）も合わせて監視する
```

`D2100 = D2000` を確認してから結果を使うのが大事です。前回の結果を誤って使わないようにするためです。

## 安全について
- 角度の結果で機械を動かす前に、**結果=1（OK）と完了番号の一致**を必ず確認してください
- 通信が途切れても、PLC側には**最後に読んだ値が残ります**。ハートビートとタイムアウトをラダーで監視し、異常時は判別結果を使わないでください
- カメラの判別は照明・汚れ・木材の重なりで誤ることがあります。角度の上下限チェックなど、ラダー側でも妥当性を確認してください
- 工場のネットワークをインターネットへ直接公開しないでください

## 机上試験（PLCなし）
PCとスマホを同じWi-Fiにつなぎ、PCで模擬PLCを動かすと、シンプルCPU通信と同じやり取りを試せます（アプリの「PLCのIPアドレス」は空欄にしておく）。

```
python ci/plc_sim.py <スマホのIP> 5000 3
→ 3秒ごとに撮影要求を出し「要求 1  OK  角度 +12.3°  信頼度 80  スマホ処理 250ms」のように表示
```

`ci/LogicTest.java` は判別処理（合成画像で角度誤差を確認）とPLC受け渡しの試験で、ビルドのたびにGitHub Actionsで実行されます。

## ビルド
GitHubにpushすると GitHub Actions が試験→APKビルドを行い、リリース「latest」に `wood-angle.apk` を置きます。スマホのブラウザでそのページを開いてダウンロード・インストールしてください（初回は「提供元不明のアプリ」の許可が必要）。

APKは毎回同じ鍵（`app/wood-angle.keystore`）で署名するので、新しい版を上書きインストールできます（個人利用アプリのための簡易運用で、鍵はリポジトリに公開しています）。

Android Studio でも開いてビルドできます（Android Gradle Plugin 8.5 / compileSdk 34 / minSdk 24）。
