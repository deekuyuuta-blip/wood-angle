# 木材角度判別（Android）— シンプルCPU通信版

スマホのカメラで**背板の木口**を見て、**平らな面（鋸で挽いた面）が上下左右のどちらを向いているか**を判別し、PLCの撮影要求に応えて結果を返すアプリです。平らな面が**下ならOK**です。木材の回転角度だけを測るモードもあります。
通信はSLMPモニタと同じく、スマホが「SLMP対応機器（QnA互換3Eフレーム）」として待ち受け、R04CPU（iQ-R）の**シンプルCPU通信**で要求の書込み・結果の読出しをしてもらいます。PLC側はパラメータ設定と、要求・結果を扱う少しのラダーだけです。

```
R04CPU ──(シンプルCPU通信／SLMP 3E・TCP)──▶ Wi-Fi ──▶ スマホ（このアプリが待受＋カメラ）
  書込み：PLCの D2000（撮影要求番号）       → スマホの D0
  読出し：スマホの D100〜D108（判別結果）   → PLCの D2100〜D2108
```

## 判別のしかた（設定で選ぶ）
| モード | 何を返すか | しくみ |
|---|---|---|
| 背板の向き（初期値） | 平らな面の向き 下・上・左・右 ＋ 傾き | 木口を背景との明るさの差で切り出し、長手方向に沿って両側の輪郭を比べる。まっすぐな側＝平らな面、外へふくらむ側＝丸い面（樹皮側） |
| 角度：輪郭 | 木材の長手方向の角度 | 形の主軸を求める |
| 角度：エッジ | 縁・木目の向きの平均 | 木材が画面からはみ出すとき用 |

- 上下左右は**画面の向き**（スマホは横向き固定）。平らな面の外向きが、真下±45°なら「下」
- 角度は右方向を 0°、反時計回りが＋、-90.0°〜+90.0°（背板モードでは平らな面の傾き）
- 「基準にする」で、今の向きを 0° にできます（スマホが少し傾いて付いているときの補正）
- 長方形に近い木口（両面とも平ら）や、正方形に近いものは信頼度が低くなり、最小信頼度（初期30）未満はNGになります

画面では、黄色の点線＝判別範囲、緑の塗り＝木口と判定した画素、赤い線＝平らな面の傾き、矢印＝平らな面の向き（下なら緑、それ以外は橙）です。

**うまく判別するコツ**
- スマホは木口の正面に、ブラケット等でしっかり固定する
- 木口と背景の明るさをはっきり変える（明るい木口なら黒っぽい背景板など）。日光が直接当たる場所は避ける
- 暗いときは「ライト」でスマホのライトを点ける
- 「範囲設定」で、木口が来る場所を指でなぞって囲む。**木口全体が範囲内に入る**ようにする（はみ出すとNG）
- 範囲内には1枚だけ映るようにする（いちばん大きいかたまりを木口とみなします）

## PLCとの受け渡し
### PLC → スマホ（PLCがシンプルCPU通信で書込む）
| スマホのデバイス | 内容 |
|---|---|
| D0 | 撮影要求番号。判別させたいとき **1〜32767 の新しい番号**を書く（0は要求なし） |

番号が変わるたびに1回判別します。同じ番号のままなら判別しません。0 にすると完了番号・結果も 0 に戻ります。

### スマホ → PLC（PLCがシンプルCPU通信で読出す）
| スマホのデバイス | 内容 |
|---|---|
| D100 | 完了番号。判別が終わると要求番号と同じ値になる |
| D101 | 結果　1=判別できた　2=NG（木口が見つからない・はみ出し・信頼度不足・向きがばらつく）　3=カメラ異常 |
| D102 | 平らな面の向き　**1=下（OK）**　2=上　3=左　4=右　0=不明（結果が1以外のとき） |
| D103 | 角度（0.1°単位の符号付き。例 123 = +12.3°） |
| D104 | 中心X（画面幅を 0〜1000） |
| D105 | 中心Y（画面高さを 0〜1000） |
| D106 | 信頼度（0〜100） |
| D107 | ハートビート（1秒ごとに+1） |
| D108 | スマホの処理時間 [ms]（要求を受けてから結果を書くまで） |

- 9ワードは1回でまとめて書くので、PLCが途中の値を読むことはありません。**D100（完了番号）＝要求番号になったら、D101・D102 を使ってください**
- **OK判定は「D101=1 かつ D102=1」**です
- 要求を受けてから「待ち時間」（初期150ms）より後に届いた画像を「平均枚数」（初期3枚）だけ使います。向きは多数決で、過半数がそろわなければNGにします。要求前の古い画像は使いません
- デバイス番号（D0・D100）は設定で変えられます

### 応答時間のめやす
スマホの処理は 待ち時間150ms＋画像3枚（約100ms）で約250ms。これにシンプルCPU通信の交信周期（書込み・読出し）が加わります。交信周期200msなら、要求から結果まで約0.4〜0.6秒です。

## スマホ側
1. PLCと同じネットワークのWi-Fiにつなぐ。**IPアドレスは固定**にする（Wi-Fi詳細設定で静的IP、またはルータでDHCP予約）
2. アプリを開き、カメラの使用を許可する（画面は横向き固定）
3. 「⚙ 設定」で、PLCのIP・待受ポート（例 5000）を設定して「保存」
4. 「待受開始」（設定で起動時に自動開始もできる）。画面に出る「このスマホのIP」をPLC側の交信先IPに設定する
5. 「範囲設定」で判別範囲を決め、背板を置いて「テスト判別」で確認。必要なら「基準にする」
6. アプリは前面に開いたままにする（画面は自動で消えません）。設定画面を開いている間や画面が消えている間はカメラが止まり、要求には「3＝カメラ異常」を返します

## PLC側（GX Works3・R04CPU）
### シンプルCPU通信の設定
1. ナビゲーション → パラメータ → R04CPU → ユニットパラメータ → 基本設定で、自ノードのIPアドレスを設定（スマホと同じネットワーク）
2. 応用設定 → シンプルCPU通信設定 →「使用する」→ 詳細設定
3. 次の2行を設定する（交信先の機種：SLMP対応機器（QnA互換3Eフレーム）、IP：スマホのIP、ポート：アプリの待受ポート）

| 交信パターン | 自局（PLC） | 交信先（スマホ） | 点数 |
|---|---|---|---|
| 書込み | D2000 | D0 | 1 |
| 読出し | D2100〜D2108 | D100〜D108 | 9 |

4. 交信周期は100〜200ms程度から。書込み後、PLCをリセット（または電源再投入）

設定画面の項目名はGX Works3のバージョンで多少違うことがあります。正確な手順はMELSEC iQ-R Ethernetユーザーズマニュアル（応用編）の「シンプルCPU通信機能」を確認してください。

### ラダーの例（考え方）
デバイスは例です。現場のラダーに合わせて置き換えてください。

```
【撮影要求】 背板が停止して判別してよい状態（例 M10）の立上りで
   D2000 を +1（32767 の次は 1 に戻す。0 は使わない）
   M2000（判別待ち）を SET、T2000（タイムアウト 2秒）を開始

【完了】 M2000 かつ D2100 = D2000 のとき
   M2000 を RST
   D2101 = 1 かつ D2102 = 1 → OK（平らな面が下）
   D2101 = 1 かつ D2102 = 2/3/4 → 向き違い（上/左/右）→ 反転・振り分けなど
   D2101 = 2 → 判別NG（木口なし・はみ出し・信頼度不足）
   D2101 = 3 → カメラ異常

【タイムアウト】 M2000 かつ T2000 がON（D2100 が要求番号にならない）
   → スマホ停止・通信異常として扱う

【監視】 D2107（ハートビート）が3秒以上変化しない
   → スマホ停止。シンプルCPU通信の交信状態（SM/SD）も合わせて監視する
```

`D2100 = D2000` を確認してから結果を使うのが大事です。前回の結果を誤って使わないようにするためです。

## 安全について
- 判別結果で機械を動かす前に、**完了番号の一致と D101=1** を必ず確認してください。NG・カメラ異常のときは安全側（停止・手動確認など）に倒してください
- 通信が途切れても、PLC側には**最後に読んだ値が残ります**。ハートビートとタイムアウトをラダーで監視し、異常時は判別結果を使わないでください
- カメラの判別は照明・汚れ・木口の欠け・重なりで誤ることがあります。立ち上げ時は「テスト判別」とログで、いろいろな背板を確かめてください
- 工場のネットワークをインターネットへ直接公開しないでください

## 机上試験（PLCなし）
PCとスマホを同じWi-Fiにつなぎ、PCで模擬PLCを動かすと、シンプルCPU通信と同じやり取りを試せます（アプリの「PLCのIPアドレス」は空欄にしておく）。

```
python ci/plc_sim.py <スマホのIP> 5000 3
→ 3秒ごとに撮影要求を出し「要求 1  判別OK  平らな面 下(OK)  角度 +2.3°  信頼度 80  スマホ処理 250ms」のように表示
```

`ci/LogicTest.java` は判別処理（合成した背板の木口80通りで向きを確認、角度誤差の確認）とPLC受け渡しの試験で、ビルドのたびにGitHub Actionsで実行されます。

## ビルド
GitHubにpushすると GitHub Actions が試験→APKビルドを行い、リリース「latest」に `wood-angle.apk` を置きます。スマホのブラウザでそのページを開いてダウンロード・インストールしてください（初回は「提供元不明のアプリ」の許可が必要）。

APKは毎回同じ鍵（`app/wood-angle.keystore`）で署名するので、新しい版を上書きインストールできます（個人利用アプリのための簡易運用で、鍵はリポジトリに公開しています）。

Android Studio でも開いてビルドできます（Android Gradle Plugin 8.5 / compileSdk 34 / minSdk 24）。
